# ADR 0003: M3 frontend decisions

**Status:** Approved by the product owner during M3 planning (2026-11-23). Numeric values are the architect's proposals that the owner approved. The owner may override any item.
**Sources:** UI_UX_SPEC sections 2 to 4, 10 to 14, and 17, PRD FR-010 to FR-018 and FR-060 to FR-064, USER_FLOWS sections 4 to 9, 19, and 20, BUSINESS_RULES sections 4, 6, and 11, ADR 0001, ADR 0002.

## Scope of M3

In scope (frontend only, in 7 parts): design tokens and primitives, the API client and data layer, the app shell and navigation, My Space with task bubbles and a list view fallback, the task detail panel and forms with lifecycle actions, bubble positions with drag, and end to end, accessibility, and performance checks.

Out of scope: any backend or OpenAPI change, Time Flow and the AI Companion beyond honest placeholders, Project Universe, Focus Mode, Memory Garden, dependencies and drag to link, recurrence, fixed commitments, week and month views, the approaching deadline warning (M5), a full History view (M6), a light theme, localization and right to left layout, and authentication.

## Decisions

1. **Bubble positions** are stored in the browser (localStorage) behind a `PositionStore` interface with `load`, `save`, `remove`, and `clear`. Key `lifespace.positions.v1`, value `{"version": 1, "positions": {"<taskId>": {"x": number, "y": number}}}`. Invalid JSON, a wrong version, or non finite numbers are treated as empty and never throw. Entries for tasks that no longer exist are removed on load. If storage is unavailable (quota or disabled) an in memory store is used and a small non blocking notice is shown. A later backend table can replace the implementation without touching callers. Positions never change a task's schedule (BUSINESS_RULES 11.1).
2. **Palette** (UI_UX_SPEC 2.2, dark first, no light theme): background #080D1B, surface #111A2E, primary #3B82F6, secondary (violet) #8B5CF6, cyan #22D3EE, success #22C55E, warning #F59E0B, danger #EF4444, text #F8FAFC, text muted #94A3B8. Derived tokens: filled primary button #2563EB, filled danger button #DC2626, focus ring cyan #22D3EE. Other hues are used only for semantic roles.
3. **Contrast** must meet WCAG AA (4.5 to 1 for text, 3 to 1 for large text and component boundaries), enforced by an automated test over the token pairs. Expected approximate values: text on background 18.6, text on surface 16.6, muted text 7.6 and 6.8, primary on background 5.3 and on surface 4.7, danger 5.2 and 4.6, violet 4.6 on background and 4.1 on surface (so violet is never used as text on the surface), cyan 10.7, success 8.5, warning 9.0, light text on the filled primary #2563EB 4.9, on the filled danger #DC2626 4.6. The original #3B82F6 with light text is only 3.5 and must not be used behind text. Colored chips may use a derived lighter text token if their tinted background needs it.
4. **Typography:** system font stack with Noto Sans Arabic as a fallback and no web font downloads. Sizes 12, 14, 16, 18, 22, 28, 36 px. Weights 400, 500, 600. Line height 1.5 for body text and 1.25 for headings.
5. **Spacing** is a 4 px grid: 4, 8, 12, 16, 24, 32, 48, 64. **Radii:** 6 px controls, 12 px panels, fully round for bubbles and chips. **Breakpoints:** 640, 1024, 1440 px.
6. **Surfaces and effects:** floating surfaces use the surface color at 80 percent opacity, a 12 px backdrop blur, and the shadow `0 8px 24px rgba(0,0,0,0.35)`. They become opaque when backdrop blur is unsupported or reduced transparency is requested. The page background is a blue radial glow at 18 percent and a violet one at 14 percent over the background color.
7. **Motion:** 150 ms for hover and focus, 250 ms for panels, at most 400 ms for layout settling, ease out. All motion is removed under `prefers-reduced-motion`.
8. **Task bubbles:** diameter = 48 + 112 x t pixels, where t = (ln(minutes) - ln(15)) / (ln(480) - ln(15)) clamped to the range 0 to 1 (15 minutes gives 48, 60 gives 93, 120 gives 115, 480 gives 160). A task without an estimate is a fixed 72 px bubble with a dashed outline and the label text "no estimate" (an estimate is never invented, BUSINESS_RULES 3.4). Priority is shown by glow plus a text chip: Critical 24 px at 55 percent alpha, High 18 px at 45, Medium 12 px at 30, Low 6 px at 15. Category is shown by an accent color, an icon, and a label: Work primary blue, Education cyan, Learning violet, Personal slate #94A3B8, Projects light blue #93C5FD. Status is shown by border style and text, never color alone: Inbox dashed border, Planned solid 2 px border, In Progress a 4 px ring plus an "In progress" chip. Overdue (the API field `is_overdue`) is a red ring plus an "Overdue" badge with an icon and text. Completed and canceled tasks are not bubbles in My Space (UI_UX_SPEC 13); they appear in the list view through its status filter.
9. **Layout:** a pure, seeded, deterministic layout engine on d3-force (layout only, no DOM) with collision and gentle category grouping. An auto organize action re runs it and clears saved positions. Pan and zoom use a transformed layer. No overlapping interactive elements.
10. **Interactions:** click selects and opens the contextual detail panel. Double click opens the panel in edit mode and never changes status. Hover shows a lightweight tooltip. The context menu (right click, or long press on touch) offers edit, start, plan, complete, cancel, reopen, and delete, only the ones that are legal for the task's status. Escape closes contextual surfaces. Dragging only moves the bubble. Every pointer action has a keyboard alternative. Drag onto another task to create a dependency is excluded.
11. **Navigation:** a compact floating dock (no sidebar, UI_UX_SPEC 3.2). My Space is active. Time Flow and AI Companion are shown as disabled items labeled "coming soon" with `aria-disabled`. The selected task lives in the URL search parameter `task` so it can be deep linked. Routing uses React Router in library mode.
12. **Forms and states:** quick add and edit forms. Quick add collects a required title and optional category, priority, estimate in minutes, and deadline. A created task is Planned (ADR 0001 item 4) with an optional "add to Inbox instead" checkbox. Server validation is authoritative: problem+json `field` messages are shown beside the field and the draft is kept (USER_FLOWS 6). Limits from ADR 0002 item 20 are shown as hints. A stale version (409 `stale_version`) shows a banner "This task changed elsewhere" with a Reload action and keeps the draft. Deleting asks for confirmation. Cancel accepts an optional reason (at most 1,000 characters). Loading uses skeletons, empty space shows an inviting empty state with one add action and a natural language example, errors show the problem message and a retry.
13. **Responsive:** below 640 px the list view is used. From 640 to 1023 px a compact spatial view. From 1024 px the full space. A list view toggle is always available as the accessibility alternative to the spatial view.
14. **Accessibility:** full keyboard operation, a visible focus ring of 2 px cyan with a 2 px offset, an `aria-live` status region for outcomes, accessible names and states on every bubble, color never the only signal, touch targets at least 44 px with at least 8 px between targets, `dir="auto"` on all user text (so Arabic titles render correctly), and `prefers-reduced-motion` and `prefers-reduced-transparency` honored.
15. **Performance targets:** 200 bubbles stay interactive and layout settles in under 500 ms. At 500 bubbles effects are reduced and off screen bubbles are not rendered. Validated in the last M3 part.
16. **Time zone:** the settings time zone (ADR 0002 item 8) is editable in M3 through a searchable list of IANA zones. When the saved zone is UTC and the browser zone differs, a non blocking hint offers to switch.
17. **Libraries:** react-router (library mode), openapi-fetch with the generated types, Radix primitives (dialog, dropdown menu, tooltip) only where needed, d3-force 3 for layout. Not added in M3: zustand, motion, react-hook-form, zod, MSW. UI state is local component state plus the URL. Every new package is installed only after checking its peer dependencies against React 19.3, TypeScript 6.0, and ESLint 9, pinned to an exact version, and never with overrides or forced installs. End to end tests use `@playwright/test` with the system browser (`channel: "chrome"`, or an `executablePath` for Chromium or Brave) and no browser download, and `@axe-core/playwright` for accessibility checks.
18. **Generated API types** are used as is. The client never invents fields. Dates from the API are shown in the saved time zone.
